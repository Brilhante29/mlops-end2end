# Technical Decision: Local Train-to-Production Stack

## Status

Accepted; package versions and the base-image OCI digest are pinned, with runtime versions reconfirmed in the three-run publication evidence.

## Selected Stack

| Concern | Selection | Problem fit |
|---|---|---|
| Runtime | Python 3.12 | Conservative common version across Airflow, MLflow, Pandera, and scikit-learn. |
| Orchestration | Apache Airflow 3.3.0 `airflow.sdk` | Stable Dag authoring, dependencies, retries, and execution evidence. |
| Tracking/registry | MLflow 3.14.0 with SQLite and local artifacts | Runs, metrics, versions, tags, and deployment aliases without a paid service. |
| Training | scikit-learn 1.9.0 logistic regression pipeline | Deterministic CPU baseline that keeps focus on lifecycle engineering. |
| Data contract | Pandera 0.32.1 | Explicit boundary validation over the DataFrame used by training. |
| Inference | FastAPI 0.136.3 and Pydantic 2.13.4 | Typed REST contract and health endpoint. |
| Telemetry | Prometheus client 0.25.0 | Portable counters, histogram, and model metadata. |
| Packaging | Official Airflow slim 3.3.0 Python 3.12 image pinned to sha256:16a6aeb38e865627e3f8e96ab0ef82d5de215153b3d8f9f5878a480136a96582 | Supported dependency baseline, 39.145% smaller than the regular reference image, and a cross-platform Docker path. |

Airflow's official constraint set is used as the compatibility reference. Application dependencies are installed while retaining `apache-airflow==3.3.0`, following the official guidance that prevents accidental Airflow upgrades or downgrades.

## Decision Brain

- Stack profile: `python-ml` with `fastapi-backend` as a secondary profile.
- API: REST HTTP. Prediction has a fixed command payload; GraphQL provides no useful client-selected shape.
- Messaging: none. No stream, fan-out, work queue, or asynchronous throughput metric exists.
- Cloud: none. Kumo is reserved for a future concrete AWS behavior, not added as decoration.
- Database: ephemeral SQLite for Airflow and MLflow metadata.
- Runtime: single CPU container, three local processes during the benchmark.

## Engineering Principles

- **SRP:** generation, validation, training, registry, policy, API, telemetry, orchestration, and measurement have separate owners.
- **OCP:** a new registry adapter implements `ModelRegistryPort`; the quality policy stays unchanged.
- **LSP:** the recording registry and MLflow registry preserve the same promotion contract; rejection must never call either.
- **ISP:** the policy sees one `promote(candidate, alias)` operation, not the MLflow client surface.
- **DIP:** the application flow depends on `ModelRegistryPort`; infrastructure depends inward.
- **KISS:** one candidate, one gate, one alias, one API, one result.
- **YAGNI:** no broker, cloud, feature store, drift engine, distributed executor, UI, or Kubernetes.
- **DRY:** quality threshold and model identity come from one settings contract; lifecycle stages do not duplicate promotion logic.

## Rejected Options

| Option | Why rejected |
|---|---|
| Prefect | Valid alternative, but Airflow is a target skill and directly supplies the Dag semantics being proved. |
| Deep neural model | Adds GPU/download variance without improving lifecycle proof. |
| Postgres | SQLite is sufficient for a single-writer ephemeral benchmark; production concurrency is out of scope. |
| Celery/Kafka/RabbitMQ | No distributed task pressure or message throughput requirement. |
| GraphQL/gRPC | One local inference operation does not need flexible selection or binary inter-service transport. |
| Managed cloud services | Violate no-secret local-first execution and obscure the measured stack. |

## API Contract

- `GET /health`: loaded model name, alias, and concrete version.
- `POST /predict`: exactly eight floats; prediction, probability, alias, and version.
- `GET /metrics`: Prometheus text exposition.
- OpenAPI is generated by FastAPI; benchmark JSON follows the portfolio benchmark contract.

## Operational Cost and Risks

- The validated image is 1.53 GB because orchestration and registry are part of the claim; the official slim base reduced it by 39.145% versus the regular reference.
- SQLite and loopback processes are not a production HA topology.
- MLflow and Airflow dependency overlap is validated by the image build, unit suite, Dag run, and service startup.
- Failure of any stage, quality gate, model load, endpoint, or metric export fails the benchmark.
